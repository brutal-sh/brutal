# Native image and PDF export parity

Reference: actual `/Applications/Pen.app`1.2.21, observed2026-10-30. Full design/functionality parity remains open.

Pen shows export controls immediately for selected layers:1×/2×/3×, PNG/JPEG/WEBP/PDF and Export layer. Switching to PDF resets image scale to1×; returning to an image retains1×. PDF shows a disabled1× scale and describes one page per layer in selection order. Multi-selection names the action Export layers (N). There is no SVG choice in this inspected menu. Open Pen keeps its extra export-row formats under Advanced properties; its compact inspector now follows the measured direct controls without adding document export settings. Format/scale preferences validate stored values against the available options. Failures retain the selection and expose retry feedback.

The existing PDF path refused Mesh because its SVG renderer deliberately refuses that paint. Mesh-containing PDF pages now use a2× raster; ordinary pages retain vector/text output. Hidden nodes and disabled Mesh paints do not trigger rasterization. Actual Pen's native256×256 Mesh PDF contains a512×512 image. A deterministic failure was reproduced before correction;28 PDF regressions now cover Mesh fills/strokes, visibility, page dimensions, ordinary output and fonts.

Executed browser delivery: direct PNG/JPEG/WEBP downloads decode as400×280 for a200×140 Mesh at2×. A reverse-order selection exports one PDF with160×100 and200×140 pages in that order. The existing Advanced rows, preview, multi-format ZIP, selected settings and Undo paths also pass. The22-path export/presentation regression passed after the codec/matte corrections. The two compact paths passed again after matching the selected-count label and PDF→image scale reset. The combined PDF/raster suite passed33 tests/92 assertions. Source/Vue/test types, full lint, architecture, locales, test placement and package/Vite/native builds passed; the installed signature was verified.

Native execution before the final codec correction produced valid512×512 PNG/JPEG files and a256×256pt one-page Mesh PDF. PDF was opened/rendered and visually inspected. Comparing JPEG from the identical file in both applications exposed black versus white alpha compositing: Open Pen was about51 RGB levels darker on an80%-opaque paint. The shared JPEG export now composites over white; PNG retains alpha. Its pixel regression passes. The installed JPEG now matches the reference sample at(10,10):94/133/174. Native WEBP initially failed despite Chromium delivery passing. The default CanvasKit build has no WebP encoder, and WKWebView cannot provide the existing browser fallback. Open Pen now has an optional host encoder hook, used only after the ordinary encoder fails. The native command reuses image0.25.10 with its WebP codec, requires the main editor, validates PNG size/dimensions/allocation and runs encoding on a blocking worker. Three Rust tests cover RGBA preservation, malformed input and a valid PNG beyond WebP dimensions. Two Core tests use the actual encoder-less CanvasKit build to check scaled-PNG handoff and failure propagation. Installed native WEBP Save succeeded. Its512×512 RGBA pixels match the final installed PNG export exactly, including80% alpha. The source tab remained clean.

Pen’s native WEBP of the same file uses a VP8L lossless image chunk. The native fallback also uses lossless WebP and does not apply a lossy quality setting. The fallback accepts PNG input up to64MiB, RGBA allocation up to256MiB and WebP dimensions up to16383 per axis. Large-image IPC overhead is unmeasured. Exact render/compression equivalence and every failure/keyboard state remain open. Actual Pen native selection of stroke then Shift-fill exported the stroke as page1 and fill as page2, visually checked in pen-native-mesh-selection-order.pdf. The same native selection order in Open Pen also exported stroke page1/fill page2, visually opened and checked. Native PDF shows1× disabled and Export layers (2); switching back to PNG retains1×.
